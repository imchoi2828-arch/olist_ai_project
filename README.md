## 프로젝트 개요

**Olist 이커머스 AI 서비스**는 브라질 이커머스 데이터를 기반으로  
추천 시스템, 리뷰 감성분석, 매출 예측, 고객 이탈 예측 기능을 하나의 웹 서비스로 구현한 프로젝트입니다.

이 프로젝트는 단순히 AI 라이브러리를 실행하는 데서 끝낸 것이 아니라,  
여러 CSV 데이터를 이해하고 병합한 뒤, 문제 유형별로 적절한 모델을 학습시키고,  
Gradio UI와 Hugging Face Spaces를 통해 실제 사용 가능한 형태로 배포한 프로젝트입니다.

<br>

### 핵심 목표

- 여러 CSV로 나뉜 Olist 데이터를 하나의 학습 가능한 데이터로 정리
- 추천, 감성분석, 매출 예측, 이탈 예측 문제를 각각 정의
- 문제 유형에 맞게 유사도 기반 추천, 딥러닝, 머신러닝 모델 적용
- 학습된 모델을 `.pkl`, `.h5` 파일로 저장
- Gradio UI와 연결하여 실제 서비스 화면 구현
- Hugging Face Spaces에 배포하여 웹에서 실행 가능하도록 구성

<br>

### 프로젝트 핵심 문장

> AI 모델은 데이터 이해와 문제 정의에서 시작된다.  
> 이 프로젝트는 이커머스 데이터를 정리하고, 문제 유형에 맞는 모델을 학습시킨 뒤, 실제 사용 가능한 서비스로 배포한 경험입니다.

## 데이터 이해

Olist 데이터는 하나의 파일이 아니라 여러 CSV가 관계형 데이터처럼 연결된 구조입니다.

| 데이터 | 의미 |
|---|---|
| customers | 고객 ID, 고객 위치 정보 |
| orders | 주문 ID, 구매 일시, 주문 상태 |
| order_items | 주문별 상품, 판매자, 가격, 배송비 |
| products | 상품 ID, 카테고리, 크기, 무게 |
| payments | 결제 수단, 결제 금액 |
| reviews | 리뷰 점수, 리뷰 텍스트 |
| sellers | 판매자 위치 정보 |
| category translation | 포르투갈어 카테고리의 영어 변환 |

<br>

이 프로젝트에서 가장 먼저 중요했던 것은 각 데이터가 어떤 키로 연결되는지 이해하는 것이었습니다.

    orders
      ↓ order_id

    order_items
      ↓ product_id

    products
      ↓ product_category_name

    payments / reviews
      ↓ order_id

    customers
      ↓ customer_id

<br>

## 데이터가 AI에 중요한 이유

AI 모델을 만들기 전에는 반드시 데이터가 학습 가능한 형태로 정리되어야 합니다.

이 프로젝트에서 직접 경험한 데이터 처리 과정은 다음과 같습니다.

- 여러 CSV 관계 파악
- 필요한 컬럼 선택
- 결측치 제거
- 중복 제거
- 문자 데이터 숫자화
- 리뷰 점수 기반 라벨 생성
- 고객 단위 데이터 재구성
- 이상치 제거
- Feature와 Target 분리

<br>

특히 감성분석과 고객 이탈 예측에서는 라벨 정의가 중요했습니다.

    감성분석 라벨
    1~2점 → 부정
    3점   → 제외
    4~5점 → 긍정

    고객 이탈 라벨
    주문 횟수 3회 이하
    그리고 최근 90일 이상 미구매
    → 이탈 가능 고객

<br>

이 과정을 통해 모델 성능은 단순히 알고리즘만으로 결정되는 것이 아니라  
**데이터 품질, 문제 정의, 라벨 설계에 크게 영향을 받는다는 것**을 배웠습니다.

<br>

## AI 모델 구현 요약

이 프로젝트에서는 하나의 모델만 사용한 것이 아니라,  
문제 유형에 따라 서로 다른 접근 방식을 적용했습니다.

| 기능 | 문제 | 모델 / 방식 |
|---|---|---|
| 추천 시스템 | 비슷한 상품 찾기 | Cosine Similarity |
| 감성분석 | 리뷰 긍정/부정 분류 | Embedding 기반 딥러닝 |
| BERT 비교 | 사전학습 모델 활용 | Hugging Face BERT |
| 매출 예측 | 결제 금액 예측 | RandomForestRegressor |
| 고객 이탈 예측 | 유지/이탈 분류 | RandomForestClassifier |

    similarity_matrix = cosine_similarity(category_matrix)

    scores = sorted(scores, key=lambda x: x[1], reverse=True)
    scores = scores[1:6]

### 배운 점

문제를 어떻게 정의하느냐에 따라 **유사도 기반 방식**으로도 기본 추천 기능을 만들 수 있다는 것을 배웠습니다.

## PART 7. 감성분석

### 목적

고객 리뷰 문장을 입력받아 긍정 리뷰인지 부정 리뷰인지 예측합니다.

<br>

### 딥러닝 처리 흐름

    리뷰 문장
       ↓
    Tokenizer
       ↓
    Sequence
       ↓
    Padding
       ↓
    Embedding
       ↓
    긍정 / 부정 예측

<br>

### 핵심 코드

출처: `STEP1_Model_Training/07_sentiment1_Tokenizer_Embedding.ipynb`

    tokenizer.fit_on_texts(X_train)
    X_train_pad = pad_sequences(X_train_seq, maxlen=100, padding="post")

출처: `STEP1_Model_Training/07_sentiment1_Tokenizer_Embedding.ipynb`

    model = Sequential([
        Embedding(input_dim=MAX_WORDS, output_dim=64),
        GlobalAveragePooling1D(),
        Dense(1, activation="sigmoid")
    ])

출처: `app.py`

    prob = sentiment_model.predict(padded, verbose=0)[0][0]

<br>

### 배운 점

딥러닝 모델은 문장을 그대로 이해하는 것이 아니라,  
문장을 숫자 배열로 바꾸고 Embedding 층을 통해 단어의 의미를 벡터로 학습합니다.

이 과정을 직접 구현하면서 자연어 처리에서  
**Tokenizer, Padding, Embedding이 왜 필요한지** 이해할 수 있었습니다.

<br>

### 직접 학습 모델과 BERT 비교

| 구분 | 직접 학습 모델 | BERT 사전학습 모델 |
|---|---|---|
| 학습 방식 | Olist 리뷰 데이터로 직접 학습 | 이미 학습된 모델 활용 |
| 장점 | 데이터 흐름과 학습 과정 이해 가능 | 별도 학습 없이 활용 가능 |
| 한계 | 데이터 양과 언어에 따라 성능 제한 | 내부 구조 해석이 상대적으로 어려움 |
| 의미 | AI 학습 과정을 직접 경험 | 실무형 사전학습 모델 활용 경험 |

## PART 8. 매출 예측

### 목적

상품 가격, 배송비, 리뷰 점수를 입력받아 예상 결제 금액을 예측합니다.

<br>

### 문제 유형

매출 예측은 긍정/부정처럼 분류하는 문제가 아니라  
`payment_value`라는 숫자를 예측하는 문제입니다.

따라서 이 파트는 **회귀 문제**입니다.

<br>

### 핵심 코드

출처: `STEP1_Model_Training/08_sales.ipynb`

    X_final = model_df[["price", "freight_value", "review_score"]]
    y_final = model_df["payment_value"]

출처: `STEP1_Model_Training/08_sales.ipynb`

    final_model = RandomForestRegressor(
        n_estimators=100,
        random_state=42
    )

    final_model.fit(X_train, y_train)

출처: `app.py`

    input_data = pd.DataFrame(
        [[price, freight_value, review_score]],
        columns=["price", "freight_value", "review_score"]
    )

<br>

### 평가 관점

| 지표 | 의미 |
|---|---|
| MAE | 평균적으로 얼마나 틀렸는지 |
| RMSE | 큰 오차를 더 크게 반영한 오차 |
| R² | 모델이 데이터를 얼마나 설명하는지 |

<br>

### 배운 점

분류 문제와 회귀 문제는 평가 방식이 다릅니다.  
이 프로젝트를 통해 문제 유형에 따라 모델뿐 아니라 평가 지표도 달라져야 한다는 것을 배웠습니다.

<br>

## PART 9. 고객 이탈 예측

### 목적

<br>

### 데이터 재구성

고객 이탈 예측은 주문 1건이 아니라 고객 1명 단위로 판단해야 합니다.  
따라서 `customer_unique_id` 기준으로 데이터를 다시 요약했습니다.

<br>

### 핵심 코드

출처: `STEP1_Model_Training/09_churn.ipynb`

    customer_df = df.groupby("customer_unique_id").agg(
        order_count=("order_id", "nunique"),
        total_payment=("payment_value", "sum"),
        avg_review=("review_score", "mean"),
        last_order_date=("order_purchase_timestamp", "max")
    ).reset_index()

출처: `STEP1_Model_Training/09_churn.ipynb`

    customer_df["churn"] = customer_df.apply(
        lambda row: 1 if row["order_count"] <= 3

        axis=1
    )

출처: `app.py`

    pred = churn_model.predict(input_data)[0]

<br>

### 배운 점

고객 이탈 예측에서 중요한 것은 모델보다 먼저  
**무엇을 이탈로 정의할 것인가**였습니다.

실제 정답 컬럼이 없는 상황에서  
주문 횟수와 최근 미구매 기간을 기준으로 이탈 라벨을 직접 정의했습니다.

이 과정을 통해 AI 프로젝트에서는 모델 학습 이전에  
**문제 정의와 라벨 설계가 매우 중요하다**는 것을 배웠습니다.

## 프로젝트를 통해 얻은 역량

### 1. 데이터를 AI 관점으로 바라보는 경험

이 프로젝트 전에는 데이터를 단순히 표 형태의 자료로만 생각했습니다.  
하지만 직접 모델을 학습시키면서 데이터는 AI가 학습하는 재료이며,  
문제 정의에 따라 같은 데이터도 전혀 다른 형태로 재구성될 수 있다는 것을 배웠습니다.

<br>

### 2. 문제 유형별 모델 선택 경험

추천, 감성분석, 매출예측, 이탈예측은 모두 AI 기능이지만 각각 문제 유형이 달랐습니다.

    추천 시스템 → 유사도 기반 접근
    감성분석 → 텍스트 분류
    매출 예측 → 회귀
    고객 이탈 예측 → 분류

이를 통해 하나의 방식으로 모든 문제를 해결하는 것이 아니라,  
문제의 성격에 맞게 모델과 평가 기준을 선택해야 한다는 것을 이해했습니다.

<br>

### 3. 딥러닝 학습 과정 경험

리뷰 감성분석 파트에서 Tokenizer, Sequence, Padding, Embedding을 사용해
  
텍스트 데이터를 직접 학습 가능한 형태로 바꾸었습니다.

이 과정을 통해 딥러닝 모델이 문장을 자동으로 이해하는 것이 아니라,  
숫자화된 데이터를 기반으로 패턴을 학습한다는 점을 체감했습니다.

<br>

### 4. 모델을 서비스로 연결한 경험

학습된 모델을 `.pkl`, `.h5` 파일로 저장하고,  
Gradio UI에서 다시 불러와 사용자가 입력한 값에 대해 예측 결과를 반환하도록 연결했습니다.

이 과정에서 AI 모델은 학습만으로 끝나는 것이 아니라,  
실제 사용 가능한 서비스 형태로 연결되어야 의미가 있다는 점을 배웠습니다.
